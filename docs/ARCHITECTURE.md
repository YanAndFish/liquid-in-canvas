# 架构

仓库是一个 pnpm workspace，分成可发布的渲染库和演示商店两部分，另有一个只在仓库内使用的 ESLint 插件：

```
packages/liquid-in-canvas   渲染库：HTML-in-Canvas + WebGPU 舞台、CSS 回退、全局默认参数
apps/demo                   演示商店（Vue）：只通过 DOM 属性和库的公开 API 使用玻璃
tools/eslint-plugin-hot     热路径规则：*.hot.ts 里每帧执行的函数不得分配堆内存
docs                        设计记录、视觉依据与性能记录
```

库不认识任何 Vue 组件，没有运行时依赖：画布渲染器直接使用 WebGPU。演示商店只从 `liquid-in-canvas`、`liquid-in-canvas/motion` 和 `liquid-in-canvas/tuner` 三个入口引入，tsconfig 用 `liquid-in-canvas/vue` 检查模板里的 `data-*` 属性，不引用库的内部文件；性能测量页和画面检查页另外从 `liquid-in-canvas/canvas` 直接使用 `CanvasStage`。

主入口不静态引入画布渲染器。`mountLiquidGlass()` 确认浏览器支持画布渲染后才动态加载 `CanvasStage`，只能使用回退实现的浏览器不会下载它（演示的生产构建里这一块压缩后 66 kB、gzip 23 kB；基于 three.js 时是 854 kB、gzip 232 kB）。

### 三种渲染方式

`mountLiquidGlass({ root, mode })` 返回统一的挂载句柄。

| 方式 | 实现 | 页面结构 | 效果 |
| --- | --- | --- | --- |
| `canvas` | `CanvasStage` | 创建 `<canvas content="drawable">`，根元素移入画布 | 折射、凸透镜放大、色散、同层融合、内容遮挡、按压形变、液体迁移 |
| `svg` | `CssGlassStage`（带折射滤镜） | 不变，另外在 `<body>` 末尾放一个隐藏的 `<svg>` 保存滤镜 | 模糊、染色、圆角、阴影，加上边缘折射、色散和按光照方向分布的轮廓高光 |
| `css` | `CssGlassStage` | 不变，只给玻璃元素写入自定义属性并安装一张样式表 | 模糊、染色、圆角、阴影、轮廓高光 |

`mode` 缺省为 `auto`：按 `canvas` → `svg` → `css` 的顺序使用浏览器支持的第一种；画布初始化失败或运行中出错时也会改用回退，并通过 `onFault` 说明原因。指定 `canvas` 时不做回退，由调用方处理错误；指定 `svg` 而浏览器不支持时得到 `css`。几种实现读取同一套 `data-glass-*` 属性、同一份全局默认参数和同一个主题来源（`liquid-glass/theme.ts`），切换时页面不需要改动。

### SVG 滤镜回退

`css/refraction.ts` 为每种尺寸与参数的玻璃生成一个滤镜，相同形状的玻璃共用。做法：

- **贴图**：逐像素按圆角矩形的有向距离算出到轮廓的深度和法线。偏移沿法线指向内部，在轮廓处最大，到偏折带内侧衰减为零；高光是贴着轮廓的细线，朝向左上光源的一侧最亮。
- **三张灰度图**：水平偏移、垂直偏移、高光各一张，在滤镜内部再放进红、蓝通道。浏览器把图片从 sRGB 转到显示器色彩空间（例如 Display P3）之后才交给滤镜，彩色像素的通道会相互串扰：中性值不再是 0.5，整块背景偏移几个像素，高光通道也会凭空多出一层白雾。灰度像素在转换前后不变。
- **顺序**：`backdrop-filter: blur() url()`，先模糊再位移，与体积着色器在折射后的位置取样模糊纹理一致。反过来写，模糊会把折射抹掉。带 SVG 折射滤镜的玻璃不再强制套用纯 CSS 回退的最低模糊与衬底下限（`FALLBACK_MIN_BLUR` / `FALLBACK_MIN_VEIL`），滤镜末尾也不额外叠加高斯模糊，允许通透材质在 `blur: 0` 下保持清澈透明；没有滤镜的纯 CSS 回退仍保留该下限以保证文字可读性。
- **色散**：红、绿、蓝各位移一次，偏移量依次增大。
- **限制**：只有 Chromium 内核会把 SVG 滤镜作用到背景上，其他内核遇到 `url()` 会让整条 `backdrop-filter` 失效，所以要同时检测语法和内核。滤镜开销与面积成正比，面积超过 12 万 CSS 像素的玻璃只用模糊。尺寸变化期间先撤下滤镜，稳定 140 ms 后再生成。

没有同层融合、内容遮挡和按压形变。

### 全局默认参数

`liquid-glass/defaults.ts` 保存一份模块级的默认参数：圆角、融合距离、悬浮高度，以及 `regular` / `clear` 两种材质在深浅主题下的外观。`parseGlassOptions()` 先读元素属性，没有声明的取默认值。`setGlassDefaults()` 合并补丁、限制取值范围并通知监听者；画布舞台和 CSS 回退都订阅了变化，会重新解析所有表面。

### 帧流水线（画布）

浏览器的 `paint` 事件驱动一帧，舞台本身没有常驻循环。按压弹簧和液体迁移运动时，以及折射场缓存等待静止或淡化的约 0.3 秒里逐显示帧请求重绘；视频播放时按视频帧请求重绘。

**视频时钟**（`video-clock.ts`）：对根元素里每个正在播放的视频登记 `requestVideoFrameCallback()`，回调里请求重绘并重新登记；暂停、播放结束、移出文档（浏览器随后在元素上触发 `pause`）和舞台销毁时用 `cancelVideoFrameCallback()` 取消，停止时与 `seeked` 时各补一次重绘。30 帧的视频在 60 Hz 的屏幕上每两个显示帧重绘一次。Chrome 157 里视频滚出视口后不再回调，也就不再重绘；回调、`requestAnimationFrame` 与 `paint` 依次发生在同一个显示帧里，画进快照的就是刚到的那一帧视频，玻璃里的折射取自同一张快照（测量见[性能记录](performance/2026-11-15-video-clock/README.md)）。浏览器没有这个接口时退回 `requestAnimationFrame` 逐显示帧请求重绘。

**显示帧探针**（`frame-probe.hot.ts`）：绘制间隔是 33 ms 时，可能是跟不上显示器，也可能是页面本来就每两个显示帧才更新一次（30 帧的视频、间歇的 DOM 更新）。浏览器自行触发的 `paint` 不经过 `invalidate()`，无法靠“谁请求了重绘”分辨；能分辨的是两次绘制之间有没有一个没有绘制的显示帧。每次绘制之后探针用 `requestAnimationFrame` 数最多两个显示帧，下一次绘制时不足两个就是连续的。自适应降级只对连续的绘制取样（见[分辨率](#分辨率)）。探针只在自适应降级开启时工作，绘制停止后数到两帧也随之停止。

1. **页面快照**：`CanvasStage` 把整个根元素上传为纹理，同时作为全屏背景和玻璃的折射源。
2. **玻璃表面**（`LiquidGlassLayer.sync`）：测量每块 `[data-liquid-glass]`，按需上传其 HTML 内容。
3. **内容遮挡**（`content-order.ts`、`ContentBackdrop`）：按层级、层叠上下文与 DOM 顺序排序；被上层玻璃覆盖的下层文字写进背景的副本，参与模糊。
4. **多级模糊**（`blur.ts`）：对合成背景逐级做高斯卷积，σ 为 2/6/16/40/80 CSS 像素；本帧用不到的层不生成。
5. **背景分级**（`stack.hot.ts`、`StackBackdrops`）：盖在其他玻璃上的组取样更高一级的背景，其中已经画好它看到的下层玻璃与内容，并在需要的范围内单独模糊；互不交叠时不生成。
6. **三维体积**（`VolumeGroups`、`volume-shader.ts`、`volume-profile-shader.ts` 或 `volume-hybrid-shader.ts`）：同层邻近玻璃合成一个距离场，按 RGB 三条光路折射取样，再叠加凸透镜偏移。混合光路里几何静止的组读取折射场缓存，见下文。
7. **前景**（`CanvasOverlay`）：`[data-stage-overlay]` 单独上传，画在低层玻璃之上。
8. **画布遍**：页面快照、前景、体积与玻璃内容按绘制顺序画进画布。

### GPU 结构

渲染器直接使用 WebGPU，不经过通用的场景图。所有绘制都是“一个矩形 + 一段 uniform”，`gpu.ts` 围绕这一点组织：

- **顶点**：顶点着色器按 uniform 开头的矩形生成四个顶点，没有顶点缓冲。
- **uniform**：一帧内所有绘制项的 uniform 先写进同一块内存，提交前一次 `writeBuffer`，绘制时用动态偏移切换。没有逐对象的缓冲和绑定组。
- **绑定**：第 0 组是 uniform 与取样器，全帧共用；第 1 组是这次绘制取样的纹理，按纹理视图缓存。
- **管线**：按键缓存。体积着色器按成员数量生成，内容着色器按遮挡数量生成；滚动中成员或遮挡变化只会取用已有的管线。启动时在后台编译常见数量（体积 1–4 名成员、遮挡 0–2 块），第一次出现更大的数量时同步编译。
- **命令**：一帧只有一个命令缓冲，依次是背景合成、模糊、各级上层背景及其模糊、折射场缓存的写入（只在某一组刚静止的那一帧）、低分辨率体积和画布遍。
- **颜色**：HTML 快照是 `rgba8unorm-srgb`，取样时由硬件解码；离屏目标是线性 `rgba16float`；画布配置为 8 位格式，以 sRGB 视图写入，混合在线性空间进行，写入时编码，不需要额外的颜色转换遍。
- **出错**：设备丢失或出现校验错误时舞台停止绘制并调用 `onFault`，`mountLiquidGlass` 据此改用回退实现。
- **计时**：设备支持 `timestamp-query` 时，测量页可以打开逐遍计时（`StageGpu.timing`），平时不写时间戳。

### 热路径

滚动和动画期间每帧都会执行的代码放在 `*.hot.ts` 文件里，这些文件里的函数不得分配堆内存。规则由 `tools/eslint-plugin-hot` 检查（`hot/no-alloc`、`hot/no-closure`），说明见它的 README。

| 文件 | 每帧做什么 |
| --- | --- |
| `stage-frame.hot.ts` | 上传页面快照，组装画布遍，编码并提交 |
| `frame.hot.ts` | uniform 分配、绘制列表排序、渲染遍编码、元素上传 |
| `CanvasOverlay.hot.ts` | 上传前景层 |
| `adaptive.hot.ts` | 按绘制间隔降级：先改用剖面光学，再调整玻璃着色倍率 |
| `frame-probe.hot.ts` | 数两次绘制之间的显示帧，判断绘制是否连续 |
| `gpu-span.hot.ts` | 隔帧写入整帧首尾两个时间戳并读回，供自适应降级判断 |
| `liquid-glass/glass-frame.hot.ts` | 测量玻璃、决定上传、排列前后顺序、写入内容 |
| `liquid-glass/content.hot.ts`、`content-order.hot.ts` | 内容与遮挡轮廓的 uniform，HTML 绘制顺序 |
| `liquid-glass/ContentBackdrop.hot.ts`、`blur.hot.ts` | 被遮挡内容的背景合成，多级模糊 |
| `liquid-glass/VolumeGroups.hot.ts`、`fusion.hot.ts`、`cover.hot.ts` | 融合分组、体积 uniform、低分辨率分块合成 |
| `liquid-glass/field-cache.hot.ts` | 混合光路的折射场缓存：比较几何特征、决定求交与淘汰 |
| `liquid-glass/flow.hot.ts`、`shared/spring.hot.ts` | 液体迁移与按压弹簧 |

做法：

- **对象池**：绘制项、分组、覆盖矩形、体积规划在池里复用；每块玻璃的矩形、体积、遮挡列表与裁剪数组在注册时创建（`liquid-glass/surface.ts`），每帧改写字段。
- **预先创建的描述对象**：渲染遍描述、动态偏移（`Uint32Array`）、元素上传的参数、画布纹理视图描述、`updateElementGeometry()` 的变换矩阵都在构造时创建。
- **管线按整数取用**：`PipelineTable.get(count)` 是一次数组读取，不拼字符串键，也不创建回调。
- **排序不用 `Array.prototype.sort`**：V8 的实现每次都分配工作数组，绘制列表与可见玻璃用插入排序。
- **冷路径分开放**：池的扩容、缓存未命中时创建对象、纹理尺寸变化写在普通文件里（`frame.ts`、`gpu-span.ts`、`liquid-glass/pools.ts`、`blur-shader.ts`、`content-shader.ts`、`volume-shader.ts`、`field-cache.ts`、`surface.ts`、`LiquidGlassLayer.ts`），热路径只在少见情况下调用。
- **DOM 读取每帧每个元素只读一次**：定位基准、裁剪区域、淡入淡出容器的矩形与透明度按帧编号缓存（`ElementBox`）；可见性用返回布尔值的 `checkVisibility()`；快照尺寸只在元素或画布尺寸变化后重新读取。DOM 接口返回的对象由 Blink 的堆管理，只能等老生代 GC 回收，规则检查不到，这是它们单独处理的原因。

数据见[性能记录](performance/2026-11-13-webgpu/README.md#追加热路径不再分配)。

### 光路：三维求交、剖面查表与逐像素混合

`CanvasStage` 的 `optics` 选项选择光路计算方式，缺省 `hybrid`。

轮廓外与浅处都是圆角矩形的有向距离，轮廓本身就是 CSS 圆角。倒角宽于圆角时，精确距离场的中轴（拐角的对角线）落在倒角里，等距线在那里折成直角，法向沿对角线突变，大面板四角会各出现一条斜线。倒角不比圆角宽的玻璃（包括胶囊）没有这个问题，两种场都退化为精确距离。处理分两种：

- **剖面查表与 SVG 回退**（`glass_contour_wide`，`css/refraction.ts` 里是同一算法）：更深处的等距线保持一段固定半径的圆角（半径取倒角超出圆角的部分，不超过圆角半径）。这两条路径只用场的法向与深度，不用梯度长度，所以画面平滑。
- **三维实体**（`glass_contour`，`raymarch`、`hybrid` 的逐步求交与折射场缓存）：坡度等于截面坡度乘以场的梯度长度，固定半径圆角的场在直边与圆弧的交界处梯度长度出现折点（等距线只有一阶连续），厚玻璃上会从切点沿对角线拉出一道亮线。改为从轮廓起按深度用 smootherstep 混合到一个超椭圆场：拐角中心沿对角线向内移 `k = 0.8 × 倒角 − 圆角`（不超过 `短边一半 − 圆角`），半径相应加大 `k`，指数随 `k` 从 2（`k = 0`，就是精确圆角）升到 4（`k ≥ 圆角的一半`），混合在 0.65 倍倒角深度内完成（`liquid-glass/contour.ts` 的三个常量）。超椭圆与直线在交界处曲率都为零，梯度长度从直边的 1 平滑降到对角线的约 0.84，没有折点；中轴移到 `圆角 + k` 以下，那里截面几乎已经平了。指数随 `k` 变化保证混合项不让梯度长度超过 1，出射光线按原步长推进仍然安全。`tests/stage/contour.test.ts` 用 TS 镜像（`tests/helpers/corner-field.ts`）检查轮廓不变、梯度长度不超过 1、交界处没有折点。

两种场只在拐角一带不同，`hybrid` 对这一带逐步求交（见下面的“拐角”），查表与求交的交界处仍然一致。`tests/visual/corner.html` 用网格背景检查。

- `raymarch`（`volume-shader.ts`）：在三维距离场里逐步求交（入射最多 64 步、每条出射光路最多 64 步，法线用有限差分），融合连接处与拐角都按三维实体折射。
  融合的实体先在平面上平滑合并各成员的轮廓，再按到合并轮廓的距离套截面（`glass_body`）。轮廓按融合距离从大到小合并，每名成员用自己的融合距离（`fuseOutlines`），结果与成员在组里的顺序无关：融合距离很小的成员（拖动时藏在按钮里的拖尾）不会因为组里另有融合距离大的玻璃，就和按钮按大的融合距离合并、整圈鼓出去。拖尾的厚度与截面按本体的尺寸算（`VolumeSurface.depthFrom`），与本体一致，不会作为较薄成员在本体轮廓上压出折痕。不是各成员三维实体的平滑合并：那样各自的倒角会在连接处相交出月牙形折痕，较薄成员的倒角在融合体里留下一圈内环。裁剪距离用平面合并权重混合，混合前截到不深于“半厚度 + 1”，没有裁剪的成员只在融合范围内把相邻成员的裁剪切面平滑推开。
  厚度、底面高度、倒角与外观不用平面合并权重混合（`fuseDominance`）：那个权重在截断处只有一阶连续，又带着各成员距离场在中轴（对角线、圆心）上的折点，小玻璃放进大玻璃中间会在顶面压出一个带棱的浅坑（画面上是从小玻璃向外放射的折痕），较薄成员也会把较厚成员靠近它的边缘削薄一圈、留下一条横线。现在成员按顶面高度排序依次并入：较厚的成员在自己的平顶范围内完全主导，往外按 smootherstep（两端一阶、二阶导数为零）让给已经合并的较薄成员，让出的范围从轮廓往外延伸“较小的融合距离 × (1 + 接近程度)”。接近程度（`Member.extra.w`，`writeFusionProximity`）按两者矩形的间距算，刚分进同一组时为 0、贴在一起时为 1，分组前后画面不跳变。大玻璃完整盖住小玻璃时形体就是大玻璃本身，拖动时藏在按钮里的拖尾也不会在按钮上留下一圈。厚度相差很大的成员贴在一起时坡度仍然陡（例如半厚度 60 与 19），较薄成员靠近较厚成员的一侧会出现全反射形成的亮带，三种光路一致。
  厚度不同的成员融合处顶面有坡，距离场在平面方向的变化率可以超过 1：`glass_body` 同时累计截面参数的坡度上界，玻璃内斜着走的出射光线按方向缩小步长（`glass_march`：竖直分量加“坡度上界 × 水平分量”），到达表面的判断仍用原距离，否则光线会越过表面，连接处出现锯齿与碎边。截面对高度的导数不超过 1，竖直的入射光线不需要缩小，否则陡坡处 64 步走不到表面，颈部会整片漏掉。`tests/visual/optics-diff.html` 不需要 HTML-in-Canvas，直接用这几种着色器在静态背景上画同一组玻璃并逐像素比较（`?scene=square` 是厚方块与调参按钮，`dx`、`dy` 移动按钮，`alone` 只画方块，`radius`、`refraction` 等覆盖方块的参数）。
- `profile`（`volume-profile-shader.ts`、`optics-lut.ts`）：实体是“平面距离 → 截面高度”的旋转体，正交入射的光线留在 (平面距离梯度, z) 平面内。冷路径对每种截面参数（倒角宽高比、曲线指数、底面倒角、色散）沿截面追踪 128 个位置，写成 `rgba16float` 查找表的一行：三条光路的横向位移与出射斜率、有效度、法线。片元只算二维平滑合并距离与解析梯度，再查表；没有逐步求交。截面参数与外观和 `raymarch` 一样由较厚成员主导；融合处距离场的梯度短于 1（截面被拉宽），查到的偏移与法线倾斜按梯度长度缩小，厚度渐变带来的顶面与底面坡度按薄棱镜近似叠加。直边、胶囊与圆角不比倒角窄的拐角上与 `raymarch` 一致（逐条照搬求交、法线与出射）；融合连接处与比倒角窄的圆角拐角是近似。

- `hybrid`（`volume-hybrid-shader.ts`）：按组、再按像素在前两者之间选择。
  - **按组**：只有一名成员、裁剪范围没有切进玻璃、圆角也不比倒角窄的组直接用剖面管线；成员多于一名的组、被 `data-glass-clip` 切开的玻璃，以及圆角比倒角窄的玻璃（`memberCornered`），用混合管线。管线在写完这一组的 uniform 之后选定（`VolumeGroups.push()`），三张管线表都按成员数量缓存。
  - **按像素**：混合着色器按到各成员轮廓（含裁剪）的距离找出最近与次近的成员。落在最近成员的平顶、次近成员不参与平滑合并时走平顶捷径；次近成员与裁剪边离得比“平滑合并的范围 + 光线在玻璃内的横向位移”更远、光路也走不到拐角里查表不准确的一带时按最近成员查表；其余像素（融合连接处、裁剪边附近、比倒角窄的圆角拐角）逐步求交。
  - **拐角**（`glass_corner`）：圆角比倒角窄时，轮廓距离场的中轴（拐角的对角线）有一段落在倒角里，等距线在那里换成不再缩小的圆弧或超椭圆，光线走到那一带就离开了截面平面。逐步求交的范围取两种场不同的区域之并：固定半径圆角的那一圈，以及超椭圆所在的、离圆心 `圆角 + k` 以内的一带，再加光线的横向位移。象限内的圆弧部分是绕圆角圆心的旋转体，光线不越过 rounding 那一圈时查表仍然准确；直边部分离对角线不近于“rounding + 横向位移”时也准确。实测 200 × 200、半厚度 60 的方块（圆角 28、倒角 48），`profile` 与 `raymarch` 差异大于 8 的像素有 7779 个，`hybrid` 降到 239 个（只剩轮廓上一圈）。
  - **横向位移**取自查找表：每行多一条纹素行，记录这个位置的三条光路在玻璃内离开入射位置的最大距离。轮廓附近发生全内反射的光线走得远，倒角内侧接近零，所以越靠内的像素越早改为查表。
  - 判定保证查表的像素上三维距离场与只有这名成员时逐点相同，所以两档交界处的结果一致，成员移动时交界连续移动；覆盖率与阴影在三档里用同一个投影距离。画面上静止的 `hybrid` 与 `raymarch` 一致。

  - **折射场缓存**（`field-cache.hot.ts`、`volume-field-shader.ts`，缺省打开，`fieldCache: false` 关闭）：求交得到的量与背景无关，组内成员的相对几何不变时也不变。几何没有明显变化满 50 ms 的组求交一次，把每个求交档像素的三条光路落点（相对像素的偏移）、入射法线、各条光路的有效程度与入射点高度写进三张纹理；之后改用读缓存的管线，每帧只读回这些量、按入射点重算一次外观的平滑合并权重，再照常取样背景与模糊。背景与视频仍然每帧更新；染色、压暗、淡入淡出不在缓存里，变化时不需要重新求交。
    - **按组的局部坐标存放**：缓存相对组内第一名成员的中心定位，纹素与着色像素对齐。整组平移（随页面滚动）不失效；裁剪边离玻璃足够远时也不算几何的一部分，玻璃在裁剪容器里滚动仍然命中。
    - **失效与运动时查表**：记录各成员相对第一名成员的几何特征（位置、尺寸、圆角、厚度、截面参数、与较薄成员的接近程度、按压与材质化、切进玻璃的裁剪边位置、色散、折射率）。
      - 小幅漂移：长度类特征每次变化不超过 1.5 像素（弹簧收敛的尾巴、轻微或很慢的拖动）不算明显变化。缓存有效时，同一帧原地重新写入，不作废、不淡出。
      - 明显变化：这一组改用剖面管线（连接处是近似），上一次的求交结果用 80 ms 淡出；没有明显变化满等待时间后重新写入（不必等旧结果淡完），从当前的比例用 100 ms 淡入。
      - 迁移中（0.6.0+）：组里有成员正在液体迁移（本体、拖尾、合并残影，`VolumeSurface.moving`）时不写入缓存，等待时间从迁移结束算起；缓存有效时出现小幅漂移也不原地重新求交，而是淡出改用查表。原来回弹在顶点前后几帧几乎不动，满 50 ms 就写入一次缓存，随后继续晃动、缓存作废，停下后再写入一次，查表与求交的差异让画面闪两次。现在迁移过程只在开始时淡出一次、结束后淡入一次。
      - 消抖（0.4.0+）：等待时间缺省 50 ms。写入后 400 ms 之内又明显变化，这一组的等待时间翻倍，最长 400 ms；稳定 800 ms 后恢复。轻微拖动不会在查表与缓存之间来回切换。
      - 等待、重新写入与淡化期间舞台继续请求重绘。
      - 不做局部失效：只让移动的成员附近改用查表、其余继续读缓存的做法，范围要外扩平滑合并、较厚成员的光线横向位移与交叉淡化，缓存本来只覆盖连接处，常见布局（工具栏旁的按钮、两张卡片、卡片角上的按钮）外扩后都盖住整个缓存，只有很宽的面板远端的小玻璃才省得下，所以整组作废。
    - **范围与显存**：只覆盖可能落在求交档的范围（两名成员都在“平滑合并范围 + 横向位移”之内的地方、裁剪边切进玻璃的一条，以及圆角比倒角窄的玻璃的整个矩形），按着色倍率分配，每个纹素 32 字节（绿色光路的偏移与法线用单精度，红蓝两条光路相对绿色的差、有效程度与高度用半精度；合计正好是 WebGPU 缺省的颜色附件上限）。全部缓存不超过 150 万纹素（48 MB）：不够时释放最久没有出现的组，单独一组就超过上限时不缓存、静止后每帧逐步求交；连续 180 帧没有出现的组释放纹理。缓存里没有光路的纹素（范围之外、轮廓上视线没有碰到实体的一圈）读取时仍然逐步求交，画面不依赖缓存是否完整。

三条路径读取同样的 uniform；`profile` 与 `hybrid` 多绑定一张查找表，放在最后（读缓存的管线在它之后再绑定三张折射场纹理）。桌面 @2 的滚动测量里 `profile` 每帧 GPU 时间约为 `raymarch` 的三分之一，见 [性能记录](performance/2026-11-14-stack-optics/README.md)；`hybrid` 不缓存时的开销取决于画面里融合连接处的面积，见 [混合光路的记录](performance/2026-11-14-hybrid-optics/README.md)；打开折射场缓存后几何静止的连接处接近 `profile`，见 [折射场缓存的记录](performance/2026-11-15-field-cache/README.md)。

### 凸透镜

玻璃顶面按拱形隆起：沿短边方向是一条抛物线，沿长边方向只在两端一个短边半径的范围内下降。取样位置朝中心偏移，偏移与拱面坡度成正比，中间区域因此被放大约 1 / (1 − `lens`) 倍；长条形的玻璃只沿短边方向放大，相当于柱面透镜。两个方向的剖面相乘，偏移在整块玻璃内连续，并与倒角处的三维折射叠加。融合区域里透镜偏移和其他外观一样由较厚成员主导。

### 嵌套玻璃与液体迁移

外层玻璃里的 `[data-liquid-glass]` 是嵌套玻璃：只有体积，没有自己的内容快照（它的 HTML 已在外层快照里）。它与外层同层，画在外层体积之后、外层内容之前，不遮挡外层内容；只与同一外层里的嵌套玻璃融合。

`data-glass-morph` 打开液体迁移（`liquid-glass/flow.hot.ts`）。体积矩形的四条边各有一根弹簧，朝运动方向的边刚度大、先到，背向的边刚度小、被拖在后面；体积被拉长时另一个方向按面积守恒的一半收窄。弹簧在元素的布局坐标里运动（定位基准内的 `offsetLeft` / `offsetTop`），滚动不会触发流动。

- **拉伸只沿坐标轴**：两条边的刚度差按 `max(0, 本轴方向分量² − 另一轴分量²)³` 加权，沿坐标轴为 1，偏离 10° 约 0.83，37° 约 0.02，沿对角线为 0；回弹让前后缘阻尼不同带来的拉开也按同样的权重（乘以拉伸，最多取 1）从前缘的阻尼过渡到后缘的阻尼。轴对齐的矩形没法斜着拉长，两个轴同时拉开只会整体放大（0.4 及以前斜向迁移时体积放大到 1.5 倍以上，看起来像一块果冻）；0.6.0 之前权重不取立方、阻尼也不加权，斜着 37° 移动时方块被拉成一根横条。斜向的拉长交给拖尾。
- **拖尾**（0.6.0 重做）：拖尾点按自己的弹簧追赶本体中心（刚度 520，阻尼按越过“回弹 × 4%”换算，接近临界），落后的距离大致与本体的速度成正比，于是拖尾总在运动的反方向，越快越长。弹簧硬、阻尼大，液体显得粘：同样速度下拖尾短而紧，本体骤停时拖尾直接收回，几乎不越过本体中心。形状是一段锥形胶囊（`VolumeTaper`，两端半径不同的两个圆的凸包）：根部的圆就是本体短边的内切圆，圆心从本体中心沿拖尾方向挪到这个圆仍完全在本体圆角矩形之内的最远处（二分求出），所以圆形和胶囊玻璃的端头本身就是根部；尾尖的圆心在拖尾点上，半径从根部的 0.78 倍随长度减到 0.5 倍，尾尖始终圆钝。拖尾点离本体中心最远到“根部偏移 + 拉伸 × 1.2 × 根部直径”。两个圆的公切线与圆相切，侧边一阶连续，所以本体后部是平滑收细的液滴形，没有颈部。0.6.0 的第一个版本用等粗胶囊，根部有一级台阶，看起来像额外接上去的部件；根部圆若比内切圆小（试过 0.88 倍），交界处会凹进一道细腰。
  - 着色器（`glass_taper`）：锥形成员 `refraction.w` 为 1，`radius` 存两端圆心相对包围盒中心的偏移，`refraction.yz` 存两端半径；`box` 仍是包围盒，分组、覆盖、阴影与透镜照旧按矩形处理。轮廓距离与法线按到两个圆和公切线的最近处求，三种光路共用；锥形成员不按圆角拐角处理（`glass_corner`、`memberCornered` 直接返回否），折射场缓存的特征里加上两端半径。
  - 沿坐标轴附近的运动：拖尾的方向按本体拉伸同样的权重（`max(0, 本轴分量² − 另一轴分量²)³`）朝坐标轴靠拢，偏离 10° 时几乎贴着轴，37° 以上基本保持原方向。否则锥形的轴相对胶囊本体略微倾斜，根部后面会平滑地鼓出几个像素。
  - 跑到前面（本体骤停、回弹往回走）：拖尾方向与迁移方向的夹角按 smoothstep 过渡，朝前时尾尖半径升到根部的 0.9 倍，拖尾点最多让尾尖越出本体前缘“0.15 × 根部半径”，并在这里被夹住、去掉向外的速度。所以骤停只让液滴前端稍微鼓一下，不会从反方向戳出一根尖。
  - 0.5 的拖尾是缩小到 0.74 的同形体积，与本体用迁移连接距离（至少 32）平滑合并。平滑合并在两者轮廓距离相近的一带往外推，最多推出连接距离的一半：分类标签从“全部”跳到“日用”时，后部鼓成一团比按钮高出近一半的液体。
  - 不变粗：根部的圆在本体之内，锥形从根部往后只会收窄，所以拖尾垂直于运动方向的跨度不超过根部直径，也就是本体的短边。拖尾与本体的连接距离取最小值 0.5：根部圆与本体端头重合，平滑合并在重合处最多外推连接距离的一半（0.25 像素）。`tests/stage/flow-shape.test.ts` 按着色器里锥形轮廓与平滑合并的公式在网格上求轮廓，检查横向、斜向与略带斜度的迁移都不比静止时粗，并且本体中心往后各个截面的宽度不先变窄再变宽（没有颈部）；另外检查匀速拖动时拖尾的落后距离，以及骤停后越出前缘的鼓包。
  - 本体同样不变粗：沿坐标轴的拉伸在另一方向按面积守恒收窄，收窄只减不增（拉长被压回时不再变宽）；晃动的放大只发生在沿运动的那一轴。斜着运动时坐标轴上的拉伸会让矩形垂直于运动方向的跨度（按圆角矩形算）超过静止时，超出的部分先从横向那一边减去，最多减到 0.35 倍，仍然超出时再减另一边。
- **回弹与晃动**：缺省 `morphBounce` / `morphWobble` 从 0.33 / 0.35 降到 0.1（0.5.0）。拉长与拖尾已经给出流动感，前缘越过目标后来回弹几下、到达后压扁拉长交替，正是“果冻”的来源。0.6.0 起回弹按越过距离线性换算阻尼比（`overshootDamping`，越过比例 `e^(−πζ/√(1−ζ²))`）：前缘越过“回弹 × 25%”，后缘“回弹 × 2.5%”，拖尾“回弹 × 30%”。原来按回弹线性插值阻尼比，0.1 时阻尼比 0.94，几乎不越过，0.33 也只越过 1.5%；缺省回弹改为 0.4，前缘越过约 10%。
- **速度**（`morphSpeed`，0.6.0+）：所有弹簧（四条边、静止尺寸、跟随拖动、晃动、拖尾）的刚度乘以速度的平方，阻尼按刚度的平方根同步放大，阻尼比不变，所以轨迹的形状不变、时间缩短为 1 / 速度。晃动的增益除以速度的平方，抵消加速度随之放大。不缩放时间步：跟随拖动的 50 ms 窗口按真实时间判断。
- **进度**：`LiquidFlow.progress()` 是四条边里离目标最远的距离相对开始时的比例，用来决定迁移连接何时断开。

迁移的来源与去向（`LiquidGlassLayer.ts`）：

- **身份**：非空的 `data-glass-morph` 是名字，标识同一块玻璃。带名字的玻璃离开后 400 ms 内同名玻璃出现时，新玻璃从旧体积的位置出发（旧体积若已经在并入别处或退去，取它当前的体积并停止那段动画）。接手的体积已经是完整的玻璃，首次显示时不从零材质化，只让内容从起点显现。同名的玻璃同时在场时不交接：0.4 及以前新玻璃会从第一块注册的同名玻璃里流出，多块同名玻璃同时在场时来源取决于注册顺序（登录表单里所有玻璃都从最早的按钮出现），所以分裂改由下面的关系显式声明。
- **分裂与合并**：`data-glass-morph-from` / `-to` 是空格分隔的名字列表，按顺序取第一块在场的玻璃，只写一侧时另一侧取同一列表，只写关系时迁移也打开（名字为空）。名字先在最近的 `data-glass-scope` 里查找，再到外层；同一层里有多块同名玻璃时取文档顺序靠前的一块。
  - 出现：是合并的时间倒放。目标中心在来源外面时，新玻璃从来源朝向目标的那条边出发：起点是贴着这条边、在来源内侧的一条细条，沿离开方向的厚度是两者较小尺寸的 0.2 倍，横向是 0.6 倍，位置是目标中心夹在来源内的点。于是前缘冲向目的地，后缘贴着来源滞后，从来源边缘拉出一道舌状液流。最初的版本从来源内部一团 0.6 倍的体积出发，先把来源鼓起一块，再整块弹出去，看不出拉出的过程。目标中心在来源里面时（例如来源让出位置、新玻璃原地长出）起点是中心对齐的 0.6 倍体积，没有拖尾。新玻璃把来源记为 `partner`。
  - 消失：并入目标，留下一块残影（`GlassGhost`）流向目标中心并缩小到消失。没有在场的目标时按普通玻璃退去。
  - 关系只在挂载与移除时生效（包括增删 `data-liquid-glass`）。启动时扫描到的玻璃直接到位；CSS 显示与隐藏走材质化，不分裂也不合并。
- **在帧里解析**：同一批 DOM 变更里注册与注销的先后不固定（React 交换元素时新旧两条记录谁先谁后都有），所以注册时只把玻璃放进 `entering`，注销时把带名字或关系的玻璃放进 `leaving` 并保留内容纹理；下一次 `sync()` 开头统一解析（`resolveMorphs()`）。先处理出现：同名交接优先，其次按 `-from` 找来源，来源本身也在等待解析时先解析来源，循环引用被跳过；再处理没被接手的离开：并入、退去或丢弃内容，同时登记 400 ms 的交接窗口。
- **迁移连接**（`VolumeSurface.link` / `linkFusion`，`fusion.hot.ts`）：迁移期间的颈部不能用两者自己的融合距离，按钮常常把融合关掉，而且平滑合并用的是后并入成员自己的融合距离，单方面调高只会让它和附近别的玻璃也连起来。改为成对的连接：分组时这一对的距离上限取 `max(各自融合距离的较小值, 连接距离)`，分成一组后在这一组里把两者的融合距离抬到连接距离。连接距离取 `max(两者融合距离, 32)`，按距离限制（中心重合时很小，避免刚出现就鼓起），并按新玻璃的进度在 50%–92% 之间用 smoothstep 降到 0，迁移结束时两者回到各自的设置。降得太早（最初是 25%–75%），而两块玻璃静止时的间距又小于融合距离，颈部在液流拉出之前就断了。合并残影与目标用同样的连接；拖尾与本体也是成对的连接，但连接距离另有上限（见上文“不变粗”）。
- **跨层**：不同层的玻璃不融合。来源在另一层时，在新玻璃的层里放一块外观同来源的残影，起点与新玻璃相同，流回来源中心并缩小，与新玻璃用迁移连接；看起来是新玻璃从来源里拉出一道颈部，随后颈部断开、缩回来源。合并时残影画在目标的层里。

以下布局变化不算迁移，体积直接到位：

- 窗口尺寸变化引起的重新排版；系统要求减少动态效果时也直接到位，也不登记分裂与合并。
- 玻璃首次显现期间（材质化的显现阶段，`reveal < 1` 且不是交接或分裂来的）：打开页面时玻璃在原处显现，不会从排版尚未稳定时的位置流过来。
- 资源加载引起的位移（`layoutSettling()`）：根元素里的 `load` 事件（捕获阶段，图片等）或 `document.fonts` 的 `loadingdone` 之后 300 ms 内，且这段时间里没有页面自己的 DOM 变更（不计舞台自己写到玻璃元素 `style` 上的重绘触发）。例如没有写尺寸的图片晚到，把下面的玻璃整体推下去时，玻璃直接落到新位置；用户操作带来的改动总伴随 DOM 变更，照常流动。

已经在流动中的玻璃不受这两条影响，继续追踪新的目标。

迁移期间内容的表现由 `data-glass-morph-content` 决定（`glass-frame.hot.ts`、`content-shader.ts`）。内容快照画在 `ContentSource.contentRect` 上，静止时它等于元素矩形，着色器跳过轮廓距离计算并走单次采样快路径：

- `static`（缺省）：内容停在元素位置；展开、收拢、交接或尺寸变形期间，片元着色器按当前玻璃体积的圆角有向距离场精确裁剪（抗锯齿圆角轮廓，不再用直角矩形裁切），并按实时形变程度与显露进度沿倒角法向内缩取样，产生类似 WWDC25 05:06–05:50 演示的边缘折射弯曲与边缘柔焦，同时向当前体积中心微移并在到位后归零；纯平移不触发裁剪与弯曲。
- `clip`：内容停在元素位置，裁剪范围每帧取体积矩形并叠加圆角 SDF 裁剪，形态变化期间同步附加边缘折射与模糊。
- `follow`：`contentRect` 取体积矩形，内容随拉伸、回弹和晃动一起变形，同时叠加圆角 SDF 裁剪与轻度边缘折射；遮挡判断也用这个矩形。
- **旧内容连续过渡（`OutgoingContent`）**：非嵌套玻璃发生同名交接、按 `data-glass-morph-to` 并入目标（残影 `GlassGhost`），或同一元素发生不小于 1.2 倍的尺寸变化（展开与收拢双向）时，旧的内容纹理不再立即销毁，而是保留约 0.24 秒随变形中的玻璃体积居中跟随、轻微按比例收紧、沿收缩倒角折射弯曲并加速模糊淡出；新内容在过渡中段从模糊与边缘折射中浮现，结束后统一释放旧纹理，避免一帧硬切或显存泄漏。

### 逐像素开销

整页快照和玻璃着色的开销都与画布像素数成正比，体积着色器是最贵的一遍。它按像素位置分三种情况：

- **轮廓之外**：投影距离大于零的像素不可能与实体相交，只画阴影。
- **平顶区域**（`glass_slab`）：像素落在某个成员的倒角内侧，且其余成员远到不参与平滑合并。实体在这里是等厚平板，光线垂直穿过，直接取样。
- **倒角与融合区域**：逐步求交，三条光路各追踪一次（色散为零时只追踪一次）。

模糊取样只读取参与插值的相邻两层。这些捷径与完整求交的结果一致，见[性能记录](performance/2026-11-13-fill-rate/README.md)。

同层玻璃靠近或重叠时会并入同一个融合组，组内每个像素都要对所有成员求距离。大面积的面板应该放到单独的层，避免和它下方的控件融合。

### 分辨率

画布分辨率与玻璃着色分辨率分开控制。

- **画布倍率**决定整页文字和玻璃上文字的清晰度，由两个静态上限决定：`maxPixelRatio`（默认 3）和 `maxPixels`（默认不限），结果不低于 1。自适应降级缺省不降低它：文字清晰度是底线。接入方把 `minPixelRatio` 设为较小的值（例如 1）才打开最后一级。
- **玻璃着色倍率**不超过画布倍率和 `maxGlassPixelRatio`（默认 2），再乘以自适应缩放。低于画布倍率时，体积组改画进低分辨率的离屏目标，再放大合成回画布（`VolumeGroups.compose()`）。玻璃后的背景本来就经过折射与模糊，降低后主要是轮廓和高光略微变软。
- **自适应降级**（`adaptive.hot.ts`）只看绘制间隔，舞台开始绘制或修改分辨率限制后的头 2 秒不采样（图片解码、字体加载造成的卡顿会让检验的基准偏高）。只有紧接着上一个显示帧的绘制才计入窗口（显示帧探针，见[帧流水线](#帧流水线画布)）：按视频帧节拍的绘制不取样，既不降级也不升回，正在进行的检验也暂停，已有的降级保持到下一段连续的绘制（滚动、动画）再评估，与绘制中断的处理相同。规则是：连续两个窗口（各 45 帧；帧很慢时满一秒且不少于 12 帧就结束）平均间隔超过 19.5 ms 时降一级，流畅 4 秒后尝试升回一级。升回后 20 秒内再变慢算升回失败：直接回到升回前的档位（不重新走阶梯），并把下次尝试推后一倍（最多 64 秒）；维持 20 秒后等待时间恢复为 4 秒。观察期要长于常见的滚动往返，否则画面里贵的一段每次滚到都会来回切一次。手段按损失从小到大排列，升回时顺序相反：
  1. 光路是 `hybrid` 或 `raymarch` 时先改用 `profile`（只有融合连接处、裁剪边与比倒角窄的圆角拐角变成近似）。
  2. 玻璃着色倍率逐级 ×0.75，最低 0.5。
  3. 画布倍率逐级降低，不低于 `minPixelRatio`，也不低于 1 与设备倍率中的较小值；整页文字随之变软。每级把像素数乘以 0.75；间隔超出很多时按“开销与像素数成正比”估计（17.5 ms ÷ 当前间隔），一级最多减半，免得连续重建好几次画布。升回时每级 ÷0.75。`minPixelRatio` 不低于静态上限给出的倍率时（缺省 `Infinity`）这一级关闭。
- **见效判断**：绘制间隔说明不了慢在哪里，所以每降一级都要检验（先忽略 10 帧重建绘制目标造成的卡顿）。基准是触发降级的两个慢窗口中较快的一个，随后连续两个窗口都要比基准缩短至少 1 ms 且至少 5%，否则撤回这一级。帧间隔按刷新周期量化（33.3、50 ms），一秒的窗口里几帧卡顿就能让均值偏离一两毫秒：只比一个窗口、或者基准取平均，都会把噪声当成见效。撤回后在 30 秒内跳过这种手段（再次无效则加倍，最多 240 秒），仍然偏慢时在同一帧里换下一种；见效但仍然偏慢则以检验期间较快的窗口为基准接着降，不再另等两个慢窗口。瓶颈是浏览器把整页画进画布时（画布像素数过多），前两种手段都会被撤回，只有画布倍率降低；瓶颈是玻璃着色时画布倍率不会被动到。
- **整帧 GPU 跨度**（`gpu-span.hot.ts`）：自适应开启、设备支持 `timestamp-query` 时每 4 帧采一次“第一遍开始 → 最后一遍结束”（第一遍写两个时间戳，其余各遍只改写结束；不逐遍相加，相邻的遍在 Apple GPU 上会重叠）。上一次读回完成前不再采样，测量页打开逐遍计时时让给它。窗口结束时取窗口内的最小值 S：GPU 被浏览器的工作占满时，个别样本会被排队拉长到数倍，最小值不受影响。要降一级时，回到 60 帧需要省下“基准 − 17.5 ms”，光路与玻璃着色倍率能省的不超过 S，需要省的更多时跳过这两种手段（画布倍率一级关闭时就什么都不改）。判据只排除，不确认：S 够大时仍按上面的检验决定去留。没有样本时与不用判据相同。数据见[性能记录](performance/2026-11-16-gpu-span/README.md)。画布尺寸的变化在 `paint` 里与窗口尺寸变化走同一条路径（`requestResize()` → `applySize()`），会重建快照纹理。

合成只覆盖体积组的包围矩形。离屏目标里各组已经相互混合，重叠的包围矩形先换成互不重叠的矩形（`cover.ts`），否则重叠处的阴影会叠加两遍。体积组按前景层的绘制顺序分成两段，各用一个离屏目标，前景层仍然夹在两段之间。低分辨率下一段内的所有体积先于这一段的内容绘制，上层玻璃的阴影因此不再压暗下层玻璃上的文字。

玻璃着色之外的开销（整页快照、页面绘制、模糊）不受玻璃着色倍率影响，只能靠降低画布倍率减少，代价是文字变软：接入方可以用两个静态上限直接限制，也可以用 `minPixelRatio` 显式打开自适应降级的最后一级。实际倍率见 `getMetrics()` 的 `dpr`，静态上限给出的倍率是 `targetDpr`。快照纹理、模糊层和玻璃内容纹理的尺寸互相独立，改变画布倍率不影响点击命中。

## DOM 约定

舞台只通过以下钩子认识页面。修改时同步 `packages/liquid-in-canvas/src/contract.ts` 与 `src/attributes.ts` 里的类型。值为 `"false"` 的约定属性视为不存在（`contract.ts` `attr()` / `hasAttr()`），框架里可以直接绑定布尔值。

| 钩子 | 舞台行为 |
| --- | --- |
| `[data-liquid-glass]` + `data-glass-*` | 注册为玻璃表面，参数见包的 README；嵌套在另一块玻璃里时只绘制体积。`data-glass-materialize="none"` 关闭生效与移除的过渡 |
| `[data-glass-scope]` + `data-glass-*` | 参数作用域：其中玻璃未声明的参数取最近作用域的值，再取更外层的作用域，最后取全局默认参数（`options.ts` `GlassAttributeSource`）。`data-glass-morph`、`-from`、`-to` 不继承；`-from` / `-to` 里的名字先在最近的作用域里查找。作用域上的参数变化时刷新其中的玻璃 |
| `[data-glass-clip]` | 限制后代玻璃与阴影的绘制范围 |
| `[data-glass-modal]` | 模态层根节点，内部玻璃不被压暗 |
| `[data-glass-scrim]` | 背景色 alpha × 模态层 opacity 决定压暗强度 |
| `[data-glass-fade]` | opacity 作用到内部玻璃 |
| `[data-glass-place="below"]`（0.4.0+） | 写在玻璃里的元素上：设为单独的 drawable，不进玻璃的内容快照（`UnderContent`）。画布里画在同层所有体积之下（`glassUnderRenderOrder`），被这块玻璃盖住的部分写进页面背景，由它折射与模糊。只对画布渲染有效 |
| `[data-stage-overlay="L"]` | 单独上传的透明前景层，盖住低于第 L 层的玻璃，被第 L 层及更高层的玻璃盖住；不写值时位于所有玻璃之上。需要在舞台 `start()` 之前存在 |

回退实现只使用前两行；裁剪、压暗和淡入淡出由浏览器按普通 DOM 处理。

| 顺序 | 内容 |
| --- | --- |
| 0 | 页面快照 |
| 900 + 10·L … +0.5 | 第 L 层玻璃的体积组 |

## 演示商店

```
src/main.ts                 启动：能力检测、渲染方式控制器、说明页
src/pages, src/components   Vue 视图：只通过 DOM 属性声明在舞台中的角色
src/composables, src/stores 视图状态：主题、语言、弹簧、购物袋、共享动画、渲染方式
src/domain, src/i18n        纯业务逻辑：商品、金额、购物袋计算与持久化
src/shared                  偏好存储与滚动容器
```

### 启动与渲染方式

`main.ts` 先检测能力。支持时以 `canvas` 方式挂载商店；不支持、初始化失败或运行时出错时卸载商店并显示 `UnsupportedView`。演示不使用 `auto`：说明页上有“使用回退版本继续”按钮，由用户决定是否以 `svg` 方式重新挂载（浏览器不支持滤镜时库自动使用 `css`）。

调参面板是库的 `liquid-in-canvas/tuner`（`src/tuner/`，原生 DOM，不依赖框架），演示的 `components/tuner/GlassTuner.vue` 只是把它插入应用 DOM 的薄封装。`RendererController`（`composables/useRenderer.ts`）通过 provide 交给这个封装，转成面板的 `GlassTunerRenderer`，用来在应用保持挂载的情况下切换渲染方式和调整分辨率。切换时根元素在文档中移动，控制器负责恢复滚动位置和视频播放。

商店内部还有三个不经过舞台的约定：`#stage-scroll`（唯一滚动容器，见 `shared/scroll.ts`）、`[data-product-image]`（共享动画的起点和终点）与 `[data-bag-target]`（加入购物袋动画的终点）。

## 测试与诊断

- `packages/liquid-in-canvas/tests`：Vitest + jsdom，覆盖属性解析、默认参数、分辨率、融合分组（含嵌套玻璃）、内容顺序、不重叠覆盖、液体迁移的弹簧与交接、回退实现（含折射滤镜的贴图取值）和不支持时的挂载行为。管线缓存、uniform 布局、绘制列表与玻璃图层的每帧逻辑用记录调用的假设备（`tests/helpers/fake-gpu.ts`）驱动真实代码检查。
- `tools/eslint-plugin-hot/tests`：热路径规则的正反用例。
- `apps/demo/tests`：领域逻辑与视图。
- `apps/demo/tests/visual/*.html`：在支持的浏览器中人工检查玻璃边缘与内容遮挡；`glass-stack.html` 检查多层叠放、生效与移除；`reference.html` 复刻参考画面的几何条件，配合 `docs/performance/2026-11-14-visual/tools/profile_fit.py` 测量折射剖面；`fusion.html` 是厚方块与调参入口按钮，检查融合连接处与圆角（`x`、`y` 固定按钮位置）。`?optics=profile`、`?optics=raymarch`、`?optics=hybrid` 切换光路，`?cache=0` 关闭混合光路的折射场缓存。
- `apps/demo/tests/perf/`：独立构建入口，通过替换 `CanvasStage.prototype.draw` 记录帧时间，`?gpu` 时打开逐遍计时，结果保存在 `docs/performance/`。`scroll.html?hold=600` 停在给定的滚动位置测量。`?lens=0` 关闭透镜，用于和没有透镜的旧版本逐像素比对（`docs/performance/2026-11-13-webgpu/tools/`）。

jsdom 不绘制 WebGPU，测试通过不能证明着色器的画面。画面需要在支持这些 API 的浏览器中检查。
