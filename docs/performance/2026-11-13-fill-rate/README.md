# 高分辨率与手机上的填充开销

2026-11-13，Chrome 157.0.8103.39，Apple Metal 3。基线为 `53b15a4` 的生产构建。高倍率和手机视口用 CDP 的 `Emulation.setDeviceMetricsOverride` 模拟，GPU 是同一台桌面机器的，**没有在真机上测量**。

## 结论

高分辨率和手机上卡顿的原因是逐像素的 GPU 开销，分成两部分：

1. **体积着色器**。DPR 2 下画布遍 5.2 ms 中它占约 4.3 ms，手机视口下占 4.8 / 5.2 ms。
2. **整页快照本身**。模拟 DPR 3（4689 × 3039）时，完全不画玻璃也只有约 47 帧。

对应三项改动：着色器跳过不需要求交的像素、限制渲染倍率、调参面板单独成层。

| 场景 | 基线 | 改动后 |
| --- | --- | --- |
| 桌面 1563 × 1013 @2，每帧 GPU 时间 | 7.4–8.1 ms | 5.4–6.3 ms |
| 同上，画布遍 | 5.2–5.3 ms | 3.4–3.7 ms |
| 手机 412 × 915 @3，每帧 GPU 时间 | 5.8–6.2 ms | 3.2 ms（倍率 2）／4.5 ms（倍率 3） |
| 桌面 1563 × 1013 @3，绘制间隔 | 27–30 ms | 16.7 ms（倍率 2） |
| 浮动面板展开并滚动，绘制间隔 | 28.2 ms | 16.7 ms |

测量路径与此前相同：`tests/perf/scroll.html` 暂停视频，八秒内往返滚动 2200 像素。

## 定位

### 各部分的开销

在基线上临时加入开关，分别关闭玻璃的各个部分（DPR 2，`?gpu`，每帧均值）：

| 构建 | GPU 合计 | 画布遍 | 模糊 |
| --- | --- | --- | --- |
| 完整 | 7.4–9.7 ms | 5.1–5.3 ms | 1.8–3.6 ms |
| 不画体积 | 3.3 ms | 0.9 ms | 2.1 ms |
| 不画玻璃 | 1.2 ms | 1.2 ms | 0 |

体积着色占画布遍的八成。模糊层的尺寸按 CSS 像素计算，不随设备倍率增长。

### 高分辨率下的下限

模拟 DPR 3 时的绘制间隔（非 `?gpu` 模式）：

| 构建 | 绘制间隔均值 | 对应帧率 |
| --- | --- | --- |
| 完整 | 26.9–29.8 ms | 约 35 帧 |
| 不画模糊 | 29.3 ms | 约 34 帧 |
| 不画体积 | 22.7 ms | 约 44 帧 |
| 不画玻璃 | 21.3 ms | 约 47 帧 |

不画玻璃时仍然达不到 60 帧，说明 1400 万像素的整页快照加一次全屏绘制已经超出预算。这部分是 HTML-in-Canvas 架构的固有开销，只能靠减少像素解决。

GPU 饱和时逐遍的时间戳会互相拖累（第一遍模糊从 1.1 ms 变成 25 ms，而它的工作量与倍率无关），因此高分辨率下只比较绘制间隔，不比较逐遍时间。

### 浮动面板

原版的客服对话框与页面玻璃同在第 0 层。同层玻璃靠近或重叠时会并入同一个融合组，组内每个像素都要对所有成员求距离。面板面积大，滚到它下面的每个商品按钮都会加入这个组：

| 构建 | 每帧 GPU 时间 | 绘制间隔 |
| --- | --- | --- |
| 基线，对话框展开 | 54.4 ms | 28.2 ms |
| 着色器优化后，面板仍在第 0 层 | 42.5 ms | 24.0 ms |
| 面板移到第 1 层 | 11.6–11.9 ms（中位数 7.1 ms） | 16.7 ms |

## 改动

### 体积着色器

`VolumeGroups.ts` 与 `volume-shader.ts`。片元按位置分三种情况：

- **轮廓之外**。实体在任意高度的距离都不小于最宽截面处的投影距离，平滑合并对两个参数单调，所以投影距离大于 0.02 的像素不可能被入射求交命中。这些像素只画阴影，不再执行最多 64 步的求交。
- **平顶区域**。像素落在某个成员的倒角内侧时，该成员在这里是等厚平板。如果其余成员的投影距离都不小于 `reach`，平滑合并不改变距离值，光线垂直入射、垂直出射，三条光路重合，没有轮廓高光。此时跳过入射求交、法线和三次出射求交，直接取样。`reach` 取 `2 × 最大融合距离 × (1 + 成员数 / 4) + 1`，是各步平滑合并影响范围的上界。
- **其余像素**走原来的路径。色散为零时三条光路重合，只追踪一次；所有光路都有效时不再取样本地柔化背景。

模糊取样原先对源纹理和五个模糊层全部取样后按权重混合，每个像素 54 次。按方差选层时相邻两层之外的权重恒为 0 或 1，现在只取样参与插值的层：平顶区域最多 4 次，其余像素最多 10 次。反射环境的三通道坐标相同，合并为一次取样。

`blur.ts` 不再生成本帧用不到的模糊层。

### 渲染倍率

`resolution.ts`。`CanvasStage` 新增 `resolution` 选项：

- `maxPixelRatio`，默认 2。DPR 3 的设备少画 2.25 倍像素。
- `maxPixels`，默认不限。
- `adaptive`，默认开启。连续两个 45 帧窗口的平均绘制间隔超过 19.5 ms 时把缩放乘以 0.85，最低 0.5；流畅 4 秒后升回一级，升回后四个窗口内再次变慢则把等待时间加倍。调整后忽略 10 帧，避免把重建画布纹理的卡顿算进去。

最初的实现一个窗口变慢就降级，展开面板的动画（约 0.8 秒）会触发一次降级再升回，画面清晰度来回变化，因此改为要求连续两个窗口。

把上限放开到 3、只靠自适应时，模拟 DPR 3 下画布在 3986 × 2583 与 3388 × 2196 之间调整，三轮绘制间隔均值为 17.4 / 16.7 / 18.5 ms。

### 调参面板的层级

`GlassTuner.vue`。面板展开期间面板与入口按钮使用第 1 层，只相互融合；收起后入口回到第 0 层。

## 画面一致性

着色器改动前后，视频暂停在第 1 秒，分别在滚动位置 0、600、1100、2300 截取 3126 × 2026 的画面逐像素比较：

| 滚动位置 | 最大差值（8 位） | 有差异的像素 |
| --- | --- | --- |
| 0 | 1 | 10 |
| 600 | 1 | 99 |
| 1100 | 0 | 0 |
| 2300 | 0 | 0 |

对比时倍率固定为 2、关闭自适应。演示商店里去掉了部分控件上显式的模糊和厚度属性（改由全局默认参数控制），这部分观感变化与着色器无关，不在对比范围内。

## 尚未解决

- 展开面板的约 0.8 秒内绘制间隔为 18.5–20 ms。面板用布局尺寸做动画，每帧重新创建内容纹理。
- 倒角与融合区域的像素仍然要做三次出射求交，是现在画布遍里最贵的部分。
- `reach` 是保守的上界。同层重叠的多成员组里，平顶捷径的适用范围比实际可行的小。
- 高分辨率下的下限来自整页快照，降低画布倍率会让文字变软。

## 追加：玻璃着色分辨率与画布分辨率分开

最初的自适应缩放降低的是整张画布的倍率，页面文字跟着变糊。现在画布保持设备倍率（上限 3），自适应只降低玻璃体积的着色倍率：体积组画进低分辨率的离屏目标，再放大合成到包围矩形上。

桌面模拟 DPR 3、画布 4689 × 3039，固定画布倍率 3，只改玻璃着色倍率（`?adaptive=0&maxPixelRatio=3&maxGlassPixelRatio=…`），绘制间隔：

| 玻璃着色倍率 | 平均间隔 | P95 |
| --- | --- | --- |
| 3（直接画进画布） | 24.3 ms | 32.6 ms |
| 2 | 21.3 ms | 26.4 ms |
| 1.5 | 20.9 ms | 26.1 ms |
| 1 | 20.0 ms | 25.8 ms |
| 画布倍率也降到 2 | 16.7 ms | 17.6 ms |

- 玻璃着色降到 2 倍就拿回了玻璃的大部分开销，剩下约 20 ms 是 1400 万像素的整页快照与页面绘制，只有降低画布倍率才能减少。
- 这组数据要看绘制间隔，不能看 GPU 时间戳。多出的离屏绘制让各遍的时间戳相互重叠，逐遍相加在 DPR 2、玻璃 1 倍时与直接绘制持平（5.4 ms），与端到端结果不符。
- 手机视口 412 × 915 @3、画布倍率 3 时，逐遍 GPU 时间为：玻璃 3 倍 4.8 ms，2 倍 5.1 ms，1.5 倍 3.9 ms，1 倍 3.0 ms。同样受时间戳重叠影响，只能说明量级。
- 自适应的级差因此取 0.75：级差太小时省下的着色抵不过多出的一遍离屏绘制。

- `tools/gpu.mjs <url> <轮数>`：第一轮预热，输出每轮的 GPU 时间、逐遍分类和绘制间隔。环境变量 `DPR`、`W`、`H` 模拟设备倍率与视口，`OPEN_PANEL=1` 先展开调参面板，`PASSES=1` 输出逐遍明细。
- 测量页接受 `?gpu`（记录 GPU 时间戳）、`?maxPixelRatio=3` 与 `?adaptive=0`（固定分辨率，用于和旧版本对比）。
- `tools/pace.js`、`tools/toggle.js`：在页面中执行的片段，分别统计四秒内的绘制间隔，以及反复展开和收起面板时的间隔。
